2. **Where the SQL comes from:** the answer's evidence already stores the executed queries — the export references the conversation/turn + result index server-side (NEVER accepts raw SQL from the client; that would bypass the agent's safety path). 3. **Data scopes still apply:** re-running happens under the same client + user scope checks as the original answer; a user whose scope changed since the answer → export re-validates against CURRENT scope (deny politely if now blocked, audit it).
4. **UI:** the existing table Export CSV button becomes "Export all N rows" when the displayed result hit the display cap (server returns the true total via a cheap COUNT when capped — or "Export CSV" unchanged when under the cap). Progress affordance for big exports (existing async/toast patterns). Locale files for the new strings.

The claim must never again be ahead of the capability.
